## 同一月度任务集怎样比较

固定任务集合T及每项验收门槛，每渠道记录所有尝试和成功任务身份，不把turn当任务。令Sa/Ss/Sr为三渠道验收成功数，Ca为全部API尝试费用，Ps为订阅月费加超额费用，Cr为中转全部尝试及固定费用。实际每成功任务成本分别Ca/Sa、Ps/Ss、Cr/Sr；分母0时无成功任务单位成本，不能记0。使用不同成功集合时还须报告未覆盖任务与质量差，不能只比较三个商。

对N项同分布任务的**假设模型**：API每提交任务全部尝试平均成本ca，成功比例qa；订阅固定Ps且成功比例qs、容量上限K。等单位成功成本条件为N=Ps·qa/(ca·qs)，只在0<N≤K、并发／期限允许且质量口径一致时有可行交点。若qs随额度变化则需逐区间求解。未公布token额度不能由月费反推K；没有quota-block事件也不能说被额度挡住的任务为0。

中转若成本F+Ncr、成功比例qr，与API比较得F·qa=N(ca·qr−cr·qa)。只有分母ca·qr−cr·qa>0且F>0才存在正交点N=F·qa/(ca·qr−cr·qa)；分母≤0时，不存在随用量增加变便宜的该种交点。若F=0，应比较cr/qr与ca/qa，无需虚构正整数交点。额外失败、重试、并发限制都要进入成本与成功集合。

这些是解题公式，不是给未知渠道套上假价格。results.json的月度成功数、额度受阻数、实际费用及两交点均null。已向作者询问三渠道具体方案；如无指定方案，继续保留未知，不要求购买或读取凭据。
