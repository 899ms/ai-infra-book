# Real RAW development and final image

Use pinned rawpy test file iss030e122639.NEF,10,656,312 bytes and verified Git blob/SHA256. This is a specified conventional RAW-development workload, not a neural image-editing model. Its purpose is to supply a real full-resolution input/output pair and measured processing service for the book's transport comparison; no AI enhancement or general photographic-quality advantage is claimed.

Pin rawpy0.27.1/Pillow12.1.1; record NumPy,LibRaw and platform versions. Decode at full resolution using AHD demosaicing, camera white balance,sRGB8-bit,default gamma(2.222,4.5),no automatic brightening, exposure multiplier1.25 and no rotation. Encode JPEGquality95,4:4:4,optimize=false,progressive=false. Preserve the first RGB output as lossless PNG and a display-size preview, plus all four independently processed JPEGs.

One warmup then three formal repetitions on Mac and on RTX CPU. Time read/decode/develop/JPEG encode and write separately; full processing ends only after writing the actual output. Filesystem writes are not claimed fsync/power-loss durable. Record source and pixels, output dimensions, exact hashes and JPEG decode error against the developed RGB. Validation requires stable dimensions, successful full JPEG decode and repeated output identity on each platform; report PSNR rather than asserting a universal visual-quality threshold. Inspect the preview before accepting the output as a usable image artifact. Cross-platform equality is measured, not presumed.

The processing is CPU-only and separate from any GPU result. It runs after the complete RAW is available. Later network replay must transfer this RAW and its actual finished JPEG, retaining the measured service provenance; it must not treat a preview as the final image or simulate partial RAW processing before upload completion.

Network stage: use actual RTX formal-run JPEG and the median of three formal RTX CPU service times. One Docker netem profile,80ms RTT/20Mbit/s/0.1% configured loss. Three shuffled repetitions of HTTP1.1/HTTP3 × reuse off/on,two sequential requests per cell,plus one warmup per protocol (26 requests). Upload complete RAW, replay measured CPU service, return complete JPEG. Client decodes every JPEG and verifies full-resolution RGB identity after byte arrival; both byte-complete and decode/validation end times are retained. This is recorded-processing replay over actual transport,not26 new RAW developments or GPU calls. No upload/processing overlap is assumed.
