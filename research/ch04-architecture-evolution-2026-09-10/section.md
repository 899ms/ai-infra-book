## 4.6 模型需求如何推动架构演进

前面分别讨论了计算单元、精度、存储、搬运和互联。实际芯片必须把这些部件组合起来：矩阵单元算得更快，操作数就要更早到达；更多中间结果留在片上，就要重新安排缓冲和同步；模型分到更多芯片，通信也进入计算的关键路径。本节把这些变化放回各家的代际演进中，具体展开图 4-3 的模型与硬件跨代协同。

比较的线索是一段 Transformer 计算：投影产生 Q、K、V，注意力依次完成 QK、Softmax、PV，前馈网络再执行矩阵与激活计算。稠密模型扩大了规则矩阵计算的规模；长上下文增加注意力的计算与状态；MoE 将前馈计算拆成许多由路由选择的专家任务；端侧生成则要求在整机内存与功耗预算中保存并反复读取模型。这些变化让各家逐渐加强相同的几类能力：专用矩阵运算、低精度执行、片上复用、异步搬运，以及不同计算单元之间的协作。

### 4.6.1 NVIDIA：从 Tensor Core 到完整的张量流水

**Volta 把规则矩阵运算交给专用单元。** 2017 年的 V100 在 SM 内加入 Tensor Core，以 FP16 输入、FP32 累加完成矩阵乘加。卷积网络的卷积可以组织成矩阵运算，全连接层本身就是矩阵乘法；同一批数据中的大量乘加因而能够共用操作数和控制逻辑。SM 中的通用计算继续处理地址、分支、激活和归约。一次神经网络计算由此在通用执行与矩阵执行之间分工，而矩阵输出怎样交给后续操作，也成为优化对象。[^volta-evolution]

**Turing 将 Tensor Core 扩展到低比特整数推理。** 在 Volta 的浮点矩阵计算基础上，Turing 增加 INT8、INT4 矩阵模式。推理中的权重和激活经过量化后，以更少位数进入矩阵单元，减少数据读取和运算成本。整数低比特与后来的 FP4 使用不同数值表示，分别需要相应的量化和缩放方法。[^turing-evolution]

**Ampere 扩展精度，并让加载与计算衔接得更紧。** A100 增加 TF32、BF16 和结构化稀疏矩阵计算。TF32 让保留 FP32 存储接口的程序使用 Tensor Core，BF16 则以较少存储保留较大的数值范围，适合深层网络训练。2:4 结构化稀疏要求一组四个位置中保留两个非零值，由数据与位置元信息共同进入矩阵单元。MoE 路由选择整个专家，2:4 约束矩阵内的元素位置，两者分别作用于任务选择和矩阵执行。与此同时，异步拷贝可以把全局内存数据直接搬到共享内存，省去寄存器中转，并与当前块的计算重叠。计算精度、操作数表示和数据搬运方式在这一代共同变化。[^nvidia]

**Hopper 围绕 Transformer 加强低精度与异步协作。** H100 的 Transformer Engine 使用 FP8，并通过缩放与精度选择管理数值范围。Tensor Memory Accelerator（TMA）接手多维张量的地址生成与搬运；warp group 矩阵指令让更大一组线程共同发起异步矩阵计算。软件可以安排一组线程准备下一块，另一组线程处理当前块。第 4.4 节的缓冲生命周期在这里对应真实的执行责任：数据搬运何时完成、矩阵单元何时用完操作数、哪个缓冲可以重新写入，都要通过同步衔接。

**Blackwell 将低精度和矩阵中间状态进一步专门化。** 数据中心 B200 的 SM100 引入支持分块缩放的低精度矩阵执行和 Tensor Memory（TMEM，张量存储），由专门的片上存储容纳矩阵累加结果。FP4 减少操作数位数，分块缩放保存局部数值范围；TMEM 改变累加器占用通用寄存器的方式，软件再将矩阵结果交给后续处理。TMA、矩阵单元与 TMEM 由此组成更完整的异步计算路径。Blackwell 的 RTX SM120 则采用另一套矩阵指令和存储组织，本章 RTX 实测对应这一实现。[^blackwell-evolution]

**Rubin 继续加速矩阵之外的注意力与专家准备工作。** 长上下文注意力包含大量指数与归约，矩阵计算加快后，Softmax 占据的时间比例会上升。Rubin 的架构说明直接将指数吞吐增强与这一瓶颈联系起来：相对 Blackwell，FP32 指数吞吐提高两倍，BF16／FP16 提高四倍。对 MoE，多个专家往往具有相同形状、不同权重地址；Rubin 的 TMA 允许在指令中更新地址与步长，使这些专家共用描述符，减少逐专家准备描述符的工作。矩阵指令还扩大了 K 维处理宽度，减少沿内积维度重复发起指令的次数。[^rubin-evolution]

| Ampere，A100 | TF32、BF16、2:4 稀疏；异步拷贝 | 训练中的数值范围、规则稀疏与分块加载 |

这条演进包含两种相互配合的变化。一种减少每次运算携带的数据和执行成本，例如 FP16、FP8、FP4；另一种减少矩阵单元前后的等待，例如异步加载、专用搬运和指数运算增强。第 4.2.3 节的注意力算例已经给出原因：矩阵与指数都需要 1,024 周期时，只把矩阵时间降至 512 周期，连续处理数据块的完成间隔仍由指数的 1,024 周期决定。Rubin 加强指数运算，正好对应这个需要同时调整资源配比的问题。

精度的演进同样包含模型和软件的配合。第 4.2.4 节的专家算例把激活分组后降低了误差，却增加了十六组计算、缩放和合并。支持分块缩放的矩阵路径把其中一部分工作纳入专门指令。DeepSeek V3 的 FP8 训练报告又从实际训练出发，提出细粒度量化和更高精度累加的硬件需求。模型执行暴露数值与调度成本，硬件提供新的低精度机制，后续模型再据此选择量化粒度与算子实现，构成图 4-3 中跨代反馈的具体过程。[^feedback]

### 4.6.2 Apple：从统一内存到 GPU 内的神经网络加速

Apple 把 CPU、GPU、Neural Engine 和内存系统组织在同一 SoC 中。CPU 负责程序控制，GPU 执行并行计算，Neural Engine 是独立的神经网络执行单元；统一内存让这些部件访问同一物理内存池。运行本地模型时，权重和 KV 由整机内存提供容量，程序通过 Metal 等接口提交 GPU 工作。CPU 与 GPU 交接数据时可以共享存储，数据是否已经写完、何时允许下一方使用，则由同步保证。[^apple]

**M1、M2 建立并扩展这一统一内存计算方式。** 随着 Pro、Max、Ultra 产品扩展 GPU 规模、内存容量与带宽，本地模型能够使用更大的存储空间。M2 Max 支持最高 96 GB 统一内存和 400 GB/s 带宽。对小 batch decode，每次调用只有少量输入行，权重读取占据较大比重；增加可用容量让更大的模型驻留，增加带宽则缩短反复读取的时间。两者分别回应第 4.3 节的容量条件与传输时间。

**M3 改变 GPU 局部存储的分配方式。** Dynamic Caching 按运行中的实际需求分配局部内存，使不同工作更充分地共享片上资源。一个算子对寄存器、线程组存储和中间结果的需求，与另一个算子并不相同；分配方式影响能同时驻留多少工作，也影响计算单元在等待期间是否还有其他工作可做。统一内存解决整机数据存在哪里，Dynamic Caching 解决 GPU 内部局部存储怎样分配，这两项机制处于不同层次。[^apple-generations]

**M4 延续 Dynamic Caching，并增强整机的 AI 计算与数据供应。** 基础 M4 的统一内存带宽为 120 GB/s，独立 Neural Engine 增强到每秒 38 万亿次操作。GPU 工作与 Neural Engine 工作各自通过相应执行路径使用硬件；在模型由 GPU 执行时，应沿 GPU 的计算、内存访问与同步分析完成时间。[^apple-generations]

**M5 将专用神经网络计算进一步放进 GPU 核心。** 每个 GPU 核心加入 Neural Accelerator，矩阵密集的工作可以在 GPU 内使用专门的加速单元；原有独立 Neural Engine 继续存在。Metal 4 的 Tensor API 为软件提供调用 GPU 内这些单元的接口。这个变化把专用矩阵计算与 GPU 的通用处理结合起来：投影、前馈网络和扩散模型中的矩阵运算使用专用能力，周围的数据处理仍由 GPU 程序组织。M5 同时引入第二代 Dynamic Caching，并将基础型号的统一内存带宽提高到 153 GB/s。[^apple]

Apple 的变化也可以用同一份 Q 投影理解。$M=1$ 时，32 MiB 权重几乎由一行输入独自读取；$M=256$ 时，这份权重被许多行共用，矩阵计算量大幅增加。前一种工作直接受益于更快的权重数据供应，后一种工作更能利用新增的矩阵计算能力。因此，统一内存带宽和 GPU 内专用计算共同决定本地模型在不同 batch 下的表现。

### 4.6.3 昇腾：从计算分工到 Cube、Vector 的高效协作

昇腾 DaVinci 从完整神经网络算子出发，把工作交给 Scalar、Vector、Cube 和 MTE：Scalar 处理控制，Vector 处理逐元素与归约，Cube 处理矩阵乘加，MTE 搬运数据。早期架构论文同时分析 ResNet、MobileNet 与 BERT，通过这些网络中不同的工作比例讨论计算和存储资源的配置。Cube 对应专用矩阵计算这条共同路线，完整 AI Core 则提供矩阵周围的向量、控制和数据通路。[^ascend-history]

**早期耦合架构把矩阵与向量计算放在同一核内。** 输入经过 L1、L0 等缓冲进入 Cube，部分和由相应累加存储保存；Vector 使用片上 Unified Buffer（UB）完成激活、归约等工作。局部缓冲将反复使用的数据留在芯片内部，MTE 安排不同存储位置之间的传递。Cube 和 Vector 能否持续工作，取决于数据准备和前后步骤的衔接。

**910B 所在的 Atlas A2 产品采用矩阵、向量分离架构。** CANN 指南将 AIC 和 AIV 分别定义为矩阵核与向量核，二者独立控制，并通过全局内存地址空间传递数据。独立控制让不同类型的工作分别推进，同时也使矩阵结果交给向量计算时的交换成本更加突出。访问经过缓存层次，交换所产生的 L2 流量与实际 HBM 流量由各级命中情况决定。[^ascend-history]

**910C 将这种计算组织扩展到双裸片封装。** CloudMatrix384 论文 v2 给出每裸片 24 个 AIC、48 个 AIV，两个裸片共同组成一颗处理器。矩阵与向量资源按一比二的核数配置，封装内连接则把两组计算和存储组织起来。论文中的 MLA 实现进一步展示了软件面对的具体问题：矩阵与向量计算如何融合、KV 使用什么布局、MTP 产生变化的 token 数后如何重新分块。模型结构进入了布局、调度与单元间交换的每一步。[^ascend-history]

**950 围绕这些交接工作改进核内通路。** 一个 AI 子系统由一个 Cube Core 和两个 Vector Core 组成。Vector 在 UB 与运算单元之间增加寄存器文件，并结合 SIMD 与 SIMT 编程；连续向量运算在寄存器中保存临时值，分支与不规则访问则通过线程式组织表达。Cube L1 Buffer 与 Vector UB 之间增加直接的 CV 数据通路，还能在传递时完成数值精度与布局转换。NDDMA 接手多维地址生成、搬运与重排，BufferID 同步用缓冲占用和释放衔接不同执行流水。950 还原生支持 MXFP8、MXFP4 等分块缩放格式，将局部缩放与低精度矩阵计算结合起来；这与 NVIDIA 加强分块缩放的变化回应同一个需求：在缩小位宽的同时管理不同数据块的数值范围。[^ascend]

| 910C／CloudMatrix384 | 双裸片；每裸片 24 AIC、48 AIV | 扩展计算与存储，处理 MLA 布局和 MTP 动态分块 |

950 白皮书明确用 FlashAttention 解释 CV 通路的用途。QK 产生分数后交给 Vector 做 Softmax，再把概率交回 Cube 做 PV。矩阵和向量之间的中间结果必须往返；把交换留在更近的存储通路，就减少了外层接口承担的工作。一个 $128\times128$ 的 FP32 张量占 64 KiB，经某交换接口写一次、读一次，共产生 128 KiB 流量。直接通路承接这一交接后，这笔读写从原交换接口移到核内通路；连续处理多个块时，原接口因而能把更多带宽用于其他数据。这正是第 4.4.3 节单元间传递问题在真实架构上的演进。

### 4.6.4 不同架构为什么走向相似的设计

三条路线的起点不同，但同一段模型计算会提出相似的要求。QK 与 PV 需要高效矩阵乘加，Softmax 需要指数与归约，前馈网络需要矩阵与激活交替，MoE 还要切换权重地址并搬运专家输入。因此，专用矩阵单元周围都需要通用处理、局部存储、数据搬运和同步。随着矩阵运算成本降低，其余工作的比例上升，下一轮改进也就逐渐转向数据供应、非矩阵计算与交接。

这些对应关系也说明，应沿完整算子比较架构。一个 Tensor Core、一个 Cube 和一个 Apple GPU 核的大小与组成不同；把 QK、Softmax、PV 分别映射到实际单元，并标出中间张量经过的存储，才能解释硬件完成了哪些工作。第 4.2.3 节分析的矩阵与非矩阵配比、第 4.3 节的存储层次和第 4.4 节的流水，在这里共同组成跨架构的分析方法。

模型也通过软件选择回应新硬件。库与编译器将矩阵运算映射到对应代际的指令，选择分块、布局和流水深度；例如 Triton 的融合注意力与持久化矩阵乘法实现，就需要组织张量描述、分块加载和不同阶段的同步。Tensor Core 提供矩阵执行能力，编译器将模型算子组织成能够使用它的程序。新单元投入使用后，软件要重新分配哪些工作由线程完成、哪些由专门引擎承担，模型才会获得完整收益。[^triton-evolution]

由此再读图 4-3，跨代协同就有了具体内容：大规模矩阵运算推动专用矩阵单元，低精度训练推动缩放与累加机制，长上下文推动注意力数据供应和指数运算，MoE 推动专家地址管理与互联，端侧生成推动统一内存容量和 GPU 内专用计算。新的计算与存储能力又改变了模型精度、批次、上下文长度和并行方式的选择。下一节进一步讨论：当某些计算与数据条件长期稳定时，硬件还能把哪些工作专门化。
