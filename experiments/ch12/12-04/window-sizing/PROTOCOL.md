# Receive limits, fixed image workload

Use the existing actual RAW/JPEG fixture unchanged (../image-records), with its measured0.483963046s CPU service replay. This stage measures actual network transfer, not new image processing. Fix container netem80ms RTT,20Mbit/s,0.1% random loss,2CPU/2GiB; all changes confined to container network namespace. Compare three independently applied receive configurations: defaults,64KiB,4MiB. Three outer trials shuffle modes. Each mode/trial starts a fresh runner/container, warms one full request per protocol, then transfers two sequential formal requests over one new reused connection per protocol. 9 subruns ×6 exchanges=54 total (36 formal18 warmups). Protocol order alternates by seeded shuffle, fixed across modes within each trial.

For TCP, set only SO_RCVBUF before connect and on listening socket before accept; leave send buffers/congestion algorithm alone. Default leaves autotuning available, explicit values lock the receive buffer. Linux readback normally doubles the requested value; SO_RCVBUF is a buffer bound, not the advertised wire window. Retain readbacks at listener/connection open/close and server TCP_INFO samples each100ms. For QUIC, set initial connection max_data and stream max_stream_data together on both endpoints; default aioquic1.3.0 values are1MiB each. These limits can dynamically expand in aioquic. Retain negotiated transport parameters and MAX_DATA/MAX_STREAM_DATA frames in qlogs. This is an application receive-limit configuration comparison, not equivalence of TCP and QUIC windows or isolated congestion-window tuning.

All application data, TLS/ALPN, source hashes, decoded final RGB, source service wait and connection reuse must validate. Retain failures and all latency samples; timeout120s common across protocols. One fresh plus one warm request per formal pair; medians do not represent pure warm connections. Server/client share event loop, qlog/sampling overhead present, netem loss positions and host scheduling can vary. No host sysctls or physical routes are modified. Image workload is intentionally used to expose sustained transfer behavior; don't generalize to smaller ASR/TTS/Computer Use payloads without measuring them.
