# 跨机器KV恢复协议

SGLang0.5.13.post1固定Qwen3-8B BF16模型与原生HiCache分页，使用公开dynamic storage入口接入本实验HTTP批量后端。GPU在rtx-pro，页文件存于Mac；仅loopback HTTP监听，通过本次独立SSH反向隧道传输。不是Mooncake/RDMA或生产分布式缓存性能。

先以固定1024token、16强制输出做生产者／全新引擎消费者功能检查。完整页内容与SHA、实际网络请求、命中来源和原响应分别保存；生产者退出后新引擎没有可继承的HBM/DRAM状态。只有成功远端get且引擎报告storage命中才能称远端复用。重复请求区分HBM命中。返回相同token不等于逐位KV或总体质量。

后续正式Chat与Agent轨迹、重复／容量／故障矩阵使用新运行目录，不把功能检查代替全部要求。控制时间包含HTTP、SSH、跨机器链路和文件页缓存；不声称物理SSD带宽、独占WAN或可靠p95。文件按临时文件rename发布但不fsync，不作掉电持久性证明。重复key内容不同即失败，不覆写证据。

功能检查003的适配：001过早退出，002的大批量上传触发120s socket超时。003每次HTTP get/set最多8页（18MiB原始KV），保留120s单调用超时，生产者最长等待600s完整输入页发布并确认client set成功，进程总上限1200s。模型、输入、输出预算与数值检查不变；不把不同批量/等待边界下时间混为性能重复样本。
