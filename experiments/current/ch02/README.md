# 当前第2章九题答案

`run.py`完成精确整数/有理数计算，`results.json`保留每项输入、完整结果与来源SHA。五模型资源数直接取已复算验证的`calculations/results/chapter2-model-comparison.json`，不重新假设其复杂执行路径。Qwen3-8B完整8K prefill的独立公式结果与该注册计算精确相等。本目录回答当前练习，不替代历史2-9的V4四题真实推理。

## 2-1 依赖图与最长链

完整节点和边在[rnn-dependencies.mmd](rnn-dependencies.mmd)与[transformer-dependencies.mmd](transformer-dependencies.mmd)，节点标注层、token位置和最早完成时刻；results.json同时保存机器可检查的DAG。

RNN节点(l,t)依赖(l,t−1)和(l−1,t)。三层、四个已知输入的最长链为3+4−1=6个单位，可按波前执行；把12个节点全部串行不是资源充足时依赖图给出的下界。Transformer节点(l,t)读取上一层位置1…t的状态，已知输入允许同层全部位置并行，三层最长链为3。

两者生成新位置的token ID都要先等最后已知位置的顶层节点(3,4)完成并产生输出分布，再采样得到新输入。不能因底层(1,4)已经完成，就提前知道待生成token。新增计算单元可减少相互独立节点争用资源造成的等待；不能消除层间依赖、RNN时间依赖或未知输出的自回归依赖。每层一个单位是题设抽象，不包括真实attention随上下文增长的运算时间或采样耗时。

## 2-2 相同投影行数，不同注意力配对数

单层投影与FFN参数数为2d²+2d·hKV·dh+3df=192,937,984。其FLOPs为2L·BP倍该值；全模型有效因果注意力为4L·hQ·dh·B[SP+P(P+1)/2]；仅各序列最后一行词表投影为2BdV。

|B/S/P|投影与FFN TFLOPs|有效注意力 TFLOPs|词表投影 GFLOPs|有效配对数（含B）|
|---|---:|---:|---:|---:|
|4/4096/1024|56.899726737408|11.133763190784|4.978638848|18,876,416|
|1/4096/4096|56.899726737408|14.844614934528|1.244659712|25,167,872|

BP相等，因此投影/FFN相同；新输入内部的三角因果部分变大，注意力不同；只投影各序列末token，B从4变1使输出头工作降到四分之一。

完整8K输入的矩阵工作为133.594323353600 TFLOPs；保留6144、只处理2048后为37.110366076928 TFLOPs，节省 **72.2215996%**。其中投影减少75%，注意力仍需让新查询访问旧前缀，输出头仍执行一次；因此总矩阵工作节省不等于75%。这里只统计题设矩阵，不把KV取回或管理成本计成零延迟结论。

## 2-3 输出、KV与累计读取

prefill产生第一个输出，后续decode次数是G−1。Qwen3-8B每位置KV=2×36×8×128×2=147,456 bytes，即144 KiB。

|G|decode次数|最终位置数|新增KV bytes|最终KV bytes|累计旧KV读取bytes|
|---|---:|---:|---:|---:|---:|
|513|512|8704|75,497,472|1,283,457,024|637,764,894,720|
|1025|1024|9216|150,994,944|1,358,954,496|1,314,184,495,104|

旧上下文读取位置数为n·8192+n(n−1)/2，不包括当前新位置的写入；最终KV为(8192+n)·144KiB。新增KV翻倍；固定输入已经占1152MiB，所以最终KV只从1224增至1296MiB，倍率18/17；累计读取因后续步骤更多且每步历史更长，超过两倍。KV位宽减半且不增加其他格式元数据时，上述三种字节量都减半，位置数和调用次数不变。最后一个返回token尚未反馈为下一步输入，不能再多加一个位置。

## 2-4 KV头与CSA

KV头8→4使每位置KV从144降为72KiB，8K总KV从1152降为576MiB。单层K/V投影参数由8,388,608降到4,194,304，全36层相应减半；Q/O投影不变。查询头仍32，查询与上下文交互的矩阵FLOPs不因共享更多KV头而减半，改变的是保存和投影的K/V宽度。

CSA按题设整除压缩：8192/4=2048条，16384/4=4096条。保存条目和索引扫描条目均翻倍；最多选512条，两种上下文都达到512上限，所以选中上限不变。这里不混入另行保存的局部窗口或压缩器固定缓冲；实际有效选择数也可能少于上限。

## 2-6 专家访问与工作量

原配置有64×8=512次token–expert分派。均匀分派时256个专家各接2个token；集中到同一组8个时这8个各接64个，其余248个为0。

两种分派的路由专家矩阵工作均为6×2048×512×512=3,221,225,472 FLOPs。均匀访问256个专家，BF16专家权重读取为1,610,612,736 bytes（1.5GiB）；集中访问8个，为50,331,648 bytes（48MiB）。这采用每个被访问专家的权重每次批执行读一次的下界，实际缓存和分块可能重复读。

改为128专家、f=1024、每token选4个后，总路由专家参数3d·f·E仍为805,306,368，实际矩阵工作6d·f·B·k也保持不变。均匀时每专家仍接2个token，集中时4个各接64个；此理想分派下相应总读取字节数也分别保持1.5GiB和48MiB。专家总数下降不自动意味着执行工作或读取量下降。

加一个共享专家f=512时另加3,145,728参数、6MiB BF16权重和402,653,184 FLOPs（B=64）；共享专家处理所有输入行，不乘路由top-k。路由器投影、门控/归约等按实际路径另计，不藏在上述专家矩阵式中。潜空间专家则在所需位置加主干→潜空间与潜空间→主干投影；若各为一个d×de矩阵、每token执行一次，两者合计2d·de参数、4B·d·de FLOPs，专家内部使用de而不是d。若实际模型按专家重复投影，必须依据其执行次数计算，不能把“一次”套给所有实现。

## 2-7 从剩余容量求请求数

Qwen3-8B精确BF16权重16,381,470,720 bytes。24GB减2GiB工作区后剩5,471,045,632 bytes用于KV；4K/8K/16K每请求分别603,979,776 / 1,207,959,552 / 2,415,919,104 bytes，因此最多 **9、4、2** 条。8K改预留3GiB后剩4,397,303,808 bytes，最多 **3** 条。

70B 4-bit使用题设39.500GB权重，48GB减2GiB工作区后剩6,352,516,352 bytes。每token320KiB，8K一条2.5GiB，可放 **2** 条；32K一条10GiB，**一条也放不下**。结果是容量上限，不包含分配器碎片、额外格式元数据、吞吐或延迟保证。

## 2-8 前缀复用和改写

S=1392，P=51，G=128，decode次数127，结束时已保存上下文1570位置；本轮新增178位置，即26,247,168 bytes（25.03125MiB）Qwen3-8B BF16 KV。

输入处理的投影行从1443降到51，减少1392行（96.465696%）。有效因果配对从1,041,846降到72,318，减少969,528对（93.058667%）。如果“本轮”还包含127次decode，两种方案的decode投影与配对完全相同：整轮投影1570→178行，降88.662420%；整轮配对1,233,235→263,707，降78.616646%。分别报告prefill和整轮，避免用不同分母比较。

修改第501个输入token时，理论最长不变前缀为前500个，新输入为1443−500=943个。真实分页缓存可能只能复用完整页而更短，不能把500当所有实现必然返回的命中量。

多卡部署还要取得实际可实现的分片和复制方式、每卡权重/状态/激活/工作区峰值、有效算力和带宽、卡间及节点间启动时延/有效传输率、collective与expert dispatch/combine时间、切分粒度与负载不均、流水调度/微批及通信计算重叠。卡数只解决总容量加法，不能直接给出任务时间。

G=1时执行一次prefill并产生首输出，后续decode调用为0；结束时输入KV长度为S+P，最后输出未再次送入模型。短语检索质量标准可规定：在固定文档中逐字返回指定键对应短语；键/值和Unicode规则预先固定，禁止额外字段、解释、重复键，要求自然停止并保存原始输出及全部失败。多题命中分母预先固定，不按模型输出挑题。

同token数比较控制输入张量长度，回答结构在相同长度下的资源差异，但不保证任务内容或难度一致；同文本比较控制任务内容，让各自tokenizer产生自己的长度，回答完成同一任务的质量和实际资源代价。两种对照均需模型版本、分词器、采样与质量标准，不能互相替代。
