# C68 / C69 状态审查

仅写本文件；未修改PLAN、公共计算或场景，未运行测试。依据当前PLAN原条目、正文及extensions第12.3–12.4、公共模块实现和实验记录范围。两项均保留未完成；原因是尚缺具体连接计算，不是笼统“没有真实无线/广域网实测”。

## C68：连接、窗口与完整任务（12.3）

原要求：首次/恢复/复用连接及多轮握手累计；30MB上传/5MB下载的非对称BDP、窗口、慢启动及丢包恢复；小请求、媒体块与完整可靠文件的不同交付条件；实验12-4在相同图片、ASR/TTS、Computer Use轨迹和网络条件下分别改变连接复用、窗口、分块、恢复，观察各自业务完成点。图12-4须关联协议时序与记录。

### 已有证据

- 正文/扩写已有20Mbit/s、100ms上行BDP=250000bytes（0.25MB）的有效手算，不应重新说BDP完全未算。
- 公共`calculations/src/infra_calc/topics/image_request_budget.py`已出现图片串行请求/连接预算，复用仅减声明connection项；RTT为输入，不是TCP/TLS/QUIC握手机制推导。它可复用而不能顶替整个C68。
- `connection_states.py`计算endpoint/peer关系及传输状态容量，**不是**HTTP连接握手、恢复或拥塞窗口模型。
- `packet_reorder.py`从真实Qwen隐藏向量构造声明分包、两路串行发送、单次成功重传和按序交付；重传延迟为给定值，明确不从ACK/超时推导，且不含头/ACK/编码。可复用事件思想，不能称完成互联网慢启动/恢复。
- `feedback_queue.py`是有限fluid队列，反馈后发送速率明确输入，不是CUBIC/BBR实现。`stream_buffer.py`是生产/消费FIFO，`audio_timing.py`已有播放时序/停顿指标，但未连接HTTP网络窗口。
- `experiments/ch12/12-04/loopback/README.md`及`analyze.py`已有192正式请求、2预热、64KiB双向载荷校验；HTTP1.1/TLS和HTTP3的复用/新连接对照。两栈仪器不同、旧连接组末才关、没有固定WAN带宽/RTT/丢包，故不能解释为纯握手消融或协议本体比较。
- `experiments/ch12/12-04/h3-multistream/README.md`及`analyze.py`已有正式144请求+18预热，共162响应的PNG字节/像素校验；一连接串行/一连接8流/四连接各2流，实际重叠达到8但整组未加速。无HTTP2匹配对照、无resumption/0RTT；它已经覆盖真实多流有限证据，不能说没有多流实验。两批均已有图。

### 确切仍缺与最小交付

1. 固定协议/版本和消息条件的握手账：fresh/resumed/reused的请求可发送/可交付依赖，多轮重复建链累计；0RTT须单列适用/拒绝回退和应用重放约束，不直接当零成本。允许按已封存RFC做声明手算，不要求重新实跑三套客户端。
2. 同一30MB/5MB及小块输入的非对称窗口事件账：初始窗口、接收/拥塞窗口、ACK推进、有限慢启动轮次、明确丢包/恢复事件与完整交付；输出BDP、发送/等待、完整请求/帧截止时间。不能将现有fluid反馈假设直接改名成CUBIC/BBR；若不模拟具体算法，应标为有限教学协议并保留固定版本算法对照待办。
3. 将这些事件作用于同一图片/语音/截图业务时间线，区分全图完成、识别结果、首次播放及截图轮时；对可靠完整文件与过期帧声明不同恢复/丢弃政策，保留共享拥塞/流控约束。现有echo完成或首响应字节不能替代这些交付点。
4. 从同结果生成图12-4，引用已有loopback/多流实测作为独立条件证据，不拼成同条件协议排名；接公共CLI/场景和独立核对。

建议PLAN状态描述：已有图片声明建链预算、BDP手算及TCP/HTTP3复用/多流真实局部记录；完整握手/窗口/恢复到相同业务轨迹的公共计算尚待。保持C68未勾选。

## C69：ACK空口、多路径与任务结果（12.4）

原要求：RAW/成片与双向语音共享空口的数据、ACK、重传；实验12-5按语音块/视觉帧速率扫描ACK频率及编码码率，比较过期、停顿和反馈延迟。实验12-6比较整图分流/备份及汇合端、乱序、蜂窝bytes/电量；语音Agent复制/切换包括音频、打断、工具结果及相关故障。12.4.3还要求截图版本/操作完成与重试及任务优先级。

### 已有证据

- `packet_reorder.py`已有声明条带化、乱序缓存、按序交付和恢复的公共子账；它的payload来自Qwen BF16向量，不是RAW或音频轨迹，路径独立速率且没有汇合端/ACK/无线开销，不能仅凭多路径命名勾选C69。
- `audio_timing.py`、`periodic_queue.py`/`feedback_queue.py`可复用播放及队列指标；未找到公共ACK频率—空口服务—媒体deadline的连接模型。反馈延迟不等于ACK空口占用。
- `experiments/ch12/12-06/README.md`、`analyze.py`和`results-summary.json`已有30正式尝试：复制/切换在健康、单连接关闭时成功，共同端点关闭10次均失败；音频有序唯一消费、取消ACK、取消后无音频与工具结果去重均验证。重复PCM5120bytes等是实际观察，相关故障负例不是待补空白。
- 该实验是同机双TCP应用夹具；应用刻意奇偶顺序不等于网络包乱序，排空所请求路径再消费不等于first-wins，拉取PCM不等于实时播放。应用JSONL/sendall bytes不包括TCP/IP/ACK/重传，不是蜂窝计费bytes或电量。已有dualpath图，但非原完整空口/费用曲线。

### 确切仍缺与最小交付

1. ACK空口有限模型：声明Wi-Fi代际或明确抽象MAC、数据/ACK包与头/前导、竞争/方向切换时间、ACK每n包或timer触发、重传事件。按同语音/视觉到达轨迹扫描ACK频率/码率，计算双向空口占用、反馈延迟、队列及过期/播放停顿；不要把TCP ACK与802.11 MAC ACK混为一种。参数可给定；无需生产Wi-Fi实测才可完成手算。
2. RAW全图的单路/分流/备份：独立路径发送与传播、汇合资源限制、按序或全量完成、故障/重复字节；蜂窝成本与能耗用明确bytes/传输时长/唤醒尾时及声明费率参数，不从应用载荷直接称实测耗电。要固定同输出/质量要求。
3. 把现有语音Agent恢复记录按真实范围公共导入，或在同任务上增加声明时序比较first-wins复制/切换；明确共同失效及取消/工具幂等性。已有30次记录不需重复运行，但尚未提供物理无线成本和播放deadline预算。
4. 对截图/操作版本与晚到结果设置有限准入/丢弃/重试例子，比较媒体、完整成片和取消信号优先级；生成图12-5的延迟/费用曲线并公共验收。

建议PLAN状态描述：已有分包乱序/恢复子账和双TCP语音取消/复制/共同故障真实证据；ACK空口频率、双向媒体期限、RAW汇合/蜂窝费用能量及应用版本重试连接仍待。保持C69未勾选。
