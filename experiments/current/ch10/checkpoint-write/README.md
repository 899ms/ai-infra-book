# 完整checkpoint载荷大小的同步存储写入

rtx-pro单次实际写入114670295040bytes（14×Qwen3-8B参数量），随后对文件执行fsync。写入99.931139360s、fsync19.114834645s，总119.045974005s，有效0.963243789GB/s。不能只取write返回时刻称落盘完成，也不把fsync视作断电／硬件故障持久性试验。

文件位于主机 `/dev/md0p1` 的ext4文件系统（挂载rw,relatime,stripe=256）。不是书中7GB/s共享存储系统，也未识别为单块SSD性能。Python3.10.12，64MiB随机块在计时前产生，循环重复写满文件，未请求稀疏分配；计时包含open、写循环和fsync，不含随机数据准备。文件大小核对精确一致，6个分散位置各读取64KiB与原块对应字节比较，通过后保存各段SHA，再删除本次生成的整个文件。未保留随机输入和大payload，不能离线重做全文件内容校验；保存的结果及源码证明本次执行走过这六处检查，不能扩大成全文件读回。

正式程序本身exit0，结果与cleanup文件已取回Mac。本次不使用GPU，不修改模型或历史checkpoint。完整原始结果在formal-001，run.log保留程序输出。单次测量不报告稳定分位数或孤立硬件因果归因，主机同期I/O可能影响速度。

`analyze.py`核对实际载荷、源码SHA、时长相加、吞吐、6处记录与删除结果，再将119.045974005s替换设计的保存时间c，其他参数不变。32／48卡推算完成35.987265753／25.744694247天；只有48卡仍满足30天。该替换只量化同等字节的本地同步存储路径影响，不包括模型序列化、CPU staging、metadata提交、跨rank协调或共享训练I/O；因此不是完整模型checkpoint延迟实测，也不是在本机跑了32／48卡训练。

重跑需要至少载荷+20GiB磁盘空闲，程序只使用自己新建的formal-001目录，已有目录拒绝覆盖。应复制脚本到新目录后执行 `python3 run.py`；无需E2B或GPU。离线重算执行 `python3 analyze.py`。
