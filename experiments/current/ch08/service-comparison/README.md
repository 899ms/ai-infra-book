# 当前8-9开放实测：共享前缀普通解码与主机上下文草稿

两条件B／E共享固定八道检索题、到达轨迹、BF16权重与KV、12GiB KV池、eager及同步调度；E仅增加主机ngram草稿（4候选，匹配窗口2—5）。每窗口16请求，4/s到达，三窗口，7秒从计划到达到最终输出的期限，按原题严格JSON标准判正确。全部输出和失败保留，不强制接受率或正确率。输入复用历史08-09，不称为8192输入／256输出的解析工作量。

每引擎先完整预热八题，再重置前缀缓存，串行预存每题前min(6144,输入长度−512)token。正式窗口之间缓存自然保留，跨窗口变热是协议的一部分，两条件顺序和请求相同。时间线保存计划／实际到达、提交、首输出事件、结束与引擎指标；stats保留KV占用与推测统计。监督器约每0.25s采样GPU总显存和利用率，属于采样峰值，可能漏掉瞬时峰值；最终须结合KV统计解读，不称精确分配峰。

运行使用rtx-pro已安装vLLM0.23环境。GPU开始前无计算进程。监督器600秒上限仅管理自身子进程组，输出到独立runs目录；失败不得覆盖。B-001与E-001均完成并通过下述独立分析。
