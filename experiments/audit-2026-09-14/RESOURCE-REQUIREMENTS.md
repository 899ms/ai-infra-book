# 暂缓的多 GPU 实验：资源与验收范围

2026-09-14 作者授权：Mac 与单 GPU RTX 上可执行的部分继续；多 GPU 测试可暂缓，但须明确缺少的资源。以下区分最小功能检查和原协议，不将缩小配置冒充原实验。

| 实验 | 需要的资源 | 获得资源后仍须验证的条件 |
| --- | --- | --- |
| 10-5 官方 Megatron 四阶段小模型 | **4 张物理 CUDA GPU**，同一 Linux 主机优先，每卡至少 2 GiB 可用显存、主机至少 8 GiB 可用内存；NCCL 点对点传输可用。PCIe 可以检验功能，不强制 NVLink。 | 固定 Core 0.16.0 官方调度器/P2P；四 rank 的输出、梯度、更新、保存张量生命周期与 allocator/profiler。依据 `ch10/10-05/PROTOCOL.md`。小模型通过后仍需原题的微批扫描及对照。 |
| 10-5 Qwen3-8B 实际训练扩展 | 建议 **4×48 GiB 或更大 CUDA GPU**、至少 128 GiB 主存，快速本地模型/检查点盘。此建议是容量准备，不是实测最低值。 | 8B 参数的混合精度 Adam 状态按常见 16 byte/参数估算约128 GB，分四级约32 GB/卡，另有激活、缓冲与框架开销；必须按最终配方重新计算。不能套用小模型2 GiB门槛。 |
| 9-6 专家放置/复制与跨卡 dispatch/combine | 至少 **2 张同型号 CUDA GPU**，建议每卡48 GiB以上；若保留现有 RTX SM120 环境，第二张 RTX PRO 6000 可减少架构变化。两卡通信需 NCCL/backend 实际支持，主机主存建议128 GiB以上。 | 先固定文本 Qwen3 MoE 或已测 Qwen3-VL 的模型身份和数值格式，再验证 EP/EPLB、相同 grouped GEMM 后端与 all-to-all。现有 VL FP8 不能自动替代正文文本 BF16；48 GiB 是准备建议，不是后端兼容保证。 |
| 9-10 A100/H20 的 PD 功能比较 | 至少 **1 张 A100 + 1 张 H20**及可测的主机/网络链路；要验证正文八卡配比则需要 **4×A100 + 4×H20**。 | 卡型、显存版本、网络吞吐与 RTT、PD引擎和KV传输兼容性均须固定；两卡功能试验不验证八卡吞吐或扩容结论。动态四卡并行变体另需4张受插件支持的同构GPU。 |
| 10-9 原作者完整 R3 配方 | 原始记录是 **8节点×8 GPU，共64 GPU**；TP4/PP2/CP2/EP4，固定 Qwen3-30B-A3B revision、NeMo RL/Megatron/TE/vLLM 版本和训练输入。 | 依据 `ch10/10-09/source-readiness/README.md` 和归档run config。GPU具体型号应从原集群记录进一步核实，不能只凭64卡数量宣称等价。需要跨节点NCCL网络、共享检查点/数据盘，并额外保存完整逐token路由、logprob与token身份；现有history未包含这些张量。可另做缩小的单卡接口检查，但不等于完整R3协议。 |
| 10-4 / 10-10 指定硬件的稳态训练与期限校准 | 所需卡数依模型、精度、优化器、batch与并行配置确定；**目前不能给出可靠的统一租用清单**。 | 首先固定缺失的目标训练配置或取得原作者匹配记录，再按状态、激活、供数、保存和恢复预算列卡数。其他模型或推理吞吐不能填补训练测量。万亿Dense情景是方案推算，不建议为完成教材而实际训练。 |

## 当前7-1的模型部署资源边界

本题要求的容量计算与分工图已完成，不要求新多卡实测。若后续验证图中的完整模型部署，按正文近似权重（V4-Pro 800GB、Kimi K3 1400GB）且每卡80GB中预留8GB计算，理想均衡容量至少分别为两台八卡服务器（16卡）和三台八卡服务器（24卡），每台可放权重576GB。服务器内高速互联、服务器间可用网络及支持相应量化和PP／TP／EP的运行时也必须具备。这是题设模型容量下界；真实检查点格式、复制和实际峰值需要部署前重新审计，特别是TP24整除和运行时支持尚未验证。单张96GB RTX不足以进行这些完整布局的物理验证。

### 当前练习9-10的混合输出容量验证

解析模型每组4×A10080GB+4×H2096GB，其中两A100给P、其余给D。复现该硬件条件的长期3.5请求/s至少需两组16卡（8A100+8H20）；10秒启动并在60秒前排空的计算条件至少三组24卡（12A100+12H20）。每组按25GB/s有效单向链路，或核验共享链路总余量。GPU秒由固定50%效率模型推算，实际部署还需验证batch32、显存workspace、启动并行与时序；这些数字不是已完成多GPU实测。详见experiments/current/ch09/README.md的9-10。
