# 10-6：检查点写入与真实训练输入共存

九次真实CPU训练比较不做中途保存、同步保存、后台线程异步保存。576次更新的输入、loss、梯度和最终完整训练状态全部精确一致，18份中途检查点在对应保存步逐状态相同。异步路径观察到实际记录读取与保存调用重叠，但这个小负载没有建立稳定的存储争用结论。

| 路径（三轮中位，毫秒） | 训练及保存完成窗口 | 首次输入获取 | 后63步输入获取合计 | 三次保存调用合计 |
|---|---:|---:|---:|---:|
| 无中途保存 | 709.393 | 522.252 | 5.449 | 0 |
| 同步保存 | 731.221 | 522.236 | 5.973 | 13.083 |
| 异步保存 | 703.899 | 518.534 | 6.853 | 15.626 |

各列分别取三轮中位，不能相加还原窗口。所有原始轮次保留：无保存窗口822.795/709.393/695.577ms，同步728.617/731.221/754.334ms，异步720.755/697.768/703.899ms。首次输入获取主要包括worker启动、首次派发／读取／IPC与packing，不能叫磁盘读取延迟。后续输入获取也包含IPC及拼接，不是纯阻塞等待。

每轮同步／异步各保存3份，实际合计4,616,593 bytes。异步三轮分别有2/3/3个记录读取调用与写入调用重叠；同步没有观测到该重叠。读取区间包括open、设置fd标志、seek、read和close；保存区间包括torch.save、文件fsync、rename和目录fsync。区间重叠不意味着设备实际传输同时进行，更不证明带宽饱和。按本组有限样本，不给worker或保存策略做通用性能排名。

## 固定执行条件

M2 Max本机CPU，Python3.14.7、Torch2.14；124672参数byte Transformer、width64两层，无dropout，同一seed1061。两个spawn DataLoader worker，每worker1线程、prefetch2、顺序返回；训练主进程2线程，64次AdamW更新，每步128个next-byte目标。正式共9个训练进程和18个实际worker，全部exit0且无残留。

沿用原真实文本的变长记录和packing，每次读取在fd上成功调用Darwin `F_NOCACHE=48`；本机SDK定义随包保存在`source/fcntl.h`。这请求关闭该fd的数据缓存，不证明物理设备字节数，也不消除设备缓存。源文本1,115,394bytes，本组只消费前32条记录，实际读取还含预取；数据规模不足以代表大模型训练供数。

保存位于第16/32/48步，sync与async都先深拷贝完全相同的状态。async使用同进程单后台线程，只允许一个未完成保存，新保存前等待前一任务。不是异步staging、独立I/O进程或GPU卸载实现。训练窗口从iterator创建后到第64步及全部中途保存完成，包含初始worker就绪等待；最终用于审计的final.pt在窗口结束后另存，不计入表中保存量。文件系统调用成功不证明断电持久性。

三轮顺序为none/sync/async、sync/async/none、async/none/sync，预登记见`PROTOCOL.md`。固定条件只执行这些正式轮次，没有失败运行需要清理。CPU和本机存储为共享环境，没有修改系统全局缓存设置或停止其他进程。

## 独立复现与核对

```sh
python -B launch.py --out new-results
python -B analyze.py --out new-results
```

在同一macOS/Torch环境独立副本执行；输出目录必须不存在。源码、真实文本和模型均随包保存，不依赖GPU、相邻实验或calculations。`environment.json`锁定执行源码SHA；`provenance.json`保存数据、模型与SDK定义SHA。

`results/`保存每步实际输入、worker读取、父进程消费／派发、staging、写入和完整训练状态。`analyze.py`从源文件位置重建输入，对所有步及模型、Adam、两份RNG和packing状态逐项精确核对，并从原始时间区间检查读取／写入重叠。派发游标受预取时序影响，完整保留而不要求等于已消费位置。

`python -B verify.py`验证既有manifest并重跑分析，要求summary逐字一致。本组补足小模型输入与保存共存的实际事件记录；更大状态、持续写入积压、设备级字节／带宽、大模型争用和最终跨session复核仍待完成。
