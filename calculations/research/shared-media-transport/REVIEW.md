# 独立审查：共享传输、媒体截止与业务交付

最终结论：**PASS（有限教学合同）**。实际执行 `python calculations/research/shared-media-transport/check-independent.py`，34 组通过：18 组独立来源/手算/边界及 16 个作者固定场景；其中非法输入覆盖 15 个实例。最终运行前后候选 SHA256 一致：`9d60611e797bb06dafd178f08ea437f2ea22c66c94224069c563a4064de4a594`。数学结果及每个固定场景的方向字节账、业务指标保存在 `check-independent.json`。本审查不修改候选实现、公共项目、PLAN 或作者结果。

## 独立性与执行范围

检查器只调用候选顶层 calculate；不调用候选调度/交付辅助函数求期望，不复制候选事件队列。A–E 期望来自实现前的 next-scope/root-hand-oracles；其他检查从实际包的发送/到达重新算串行资源、区间唯一覆盖、发送方 ACK 可见信用、交付前驱、应用依赖与播放递推。来源的六份封存原件逐份再次重读核对 bytes/SHA，已读条款及限制见 SOURCE-SCOPE.md。

最终运行实际计算了完整 30,000,000-byte 上传/5,000,000-byte 回传、混合 ASR/TTS/截图、额外预览、完整/过期截图及不可靠丢失无反馈场景。不是只核小例、只读取作者预生成 JSON，或把逻辑区间做并集后忽略重发次数。

## 手算与边界结果

| 检查 | 独立期望与实际结果 |
|---|---|
| A 固定发送记录的 HOL | 逐流音频交付 3 s，整体有序 7 s；图像两者均 7 s。全部发送记录相同，data wire 4 bytes、唯一有效 3 bytes |
| B 同分包调度 | FIFO 图像/音频完成 5/6 s；音频优先 6/3 s。单个 4-byte 已开始图像包不能抢占，音频仍 6 s 到达 |
| C 共享信用 | 一流或三流，数据开始均为 0/1/4 s，前两 ACK 到达为 4/5 s。第三包不能用接收方在 2 s 已知的状态提前发送 |
| D 播放 | 3/6/7 s 到达、每块 2 s：可靠播放 3–5/6–8/8–10，停顿 1 s；固定槽缺第二块，缺音 2 s，第三块到达恰在 7 s 可播放 |
| E 完整图像 | 全图 7 s 才启动 2 s 工作；成片反向发送 9–11，加传播到 12 s。早到音频不提前整图工作 |
| E 取消与非抢占 | 取消到服务器为 4 s，已开始工作仍为 2–5 s，未发响应被抑制；已在途响应仍到达并保留 bytes |
| 取消端点与交付 | 服务器收到取消不让客户端同 tag 的待发包/工作瞬间消失；取消与发送同刻先更新接收端状态。可靠取消受 HOL 时在 7 s 才生效，逐流为 3 s，不能在网络到达 3 s 偷先执行尚未交付的应用控制 |
| 不可靠媒体信用 | 免可靠接收/逐流信用，但仍占共享发送信用；永久损失且无反馈时保留信用并输出未完成。该单元不成为可靠流有序前驱 |
| 截止与版本等号 | 到达恰在 deadline 可交付；晚到即使超期仍保留发送占用；未发超期无 data wire。客户端截图版本在完成同刻更新使旧结果不可用，更新晚于完成则不影响该完成时刻可用性 |
| 调度消融 | 网络 priority 不改变默认 CPU FIFO；只有显式 compute_scheduler 才改变任务优先级。mixed FIFO/priority 原始输入移除 scheduler 后完全相同 |
| 业务完成 | 全部 expired 可使 unfinished 为空，但 all_businesses_usable 为 false；可靠播放缺块的已播前缀不是完整播放，unresolved 与 complete_playback 单列 |

15 个拒绝例覆盖零速率、bool 冒充整数信用、区间空洞、可靠数据过期、未知/循环依赖、不可靠重传、跨端无消息依赖、非法播放政策/负时长/空 required/乱序版本，以及跨接收端聚合业务和不可靠成片。它们是必要边界，不声称穷举全部无效 JSON。

## 完整图像逐方向字节账

`image-30mb-5mb` 使用 25,000-byte 教学数据单元和每单元 40-byte 声明头；ACK 为 40 bytes。以下方向按**实际出口**列出：

| 实际出口 | 数据 payload | 数据头 | 数据 wire | ACK wire | 恢复 payload |
|---|---:|---:|---:|---:|---:|
| c2s | 30,000,000 | 48,000 | 30,048,000 | 8,000 | 0 |
| s2c | 5,000,000 | 8,000 | 5,008,000 | 48,000 | 0 |

完整唯一收到/交付为 35,000,000 bytes；完整成片到达 `1008391/78125` s。每个实际发送都独立核对 offset/end、attempt、序列化时长、传播、方向和 ACK；每条方向的 ACK 与数据区间均无重叠。恢复例另外验证同逻辑区间的新 attempt 不增加唯一贡献，仍增加 wire，固定信用只释放一次。混合场景方向账全部保存在 JSON，不能用完整图片的 35 MB 代替音频/截图/取消的额外 bytes。

mixed FIFO 中全部 8 个 TTS 槽缺失；priority 下全部 8 块播放、first_play 为 2/5 s。两者是同一**提供给发送器的**业务输入，但因期限/取消产生不同实际发送字节，不要求两者实际 wire 相等。混合截图仍可能被取消或变成旧版本；独立 screenshot-complete 给可用完整轮次，stale 场景给负例，不能把混合任务称全部成功。额外 preview 的工作、wire 与 preview_complete 已分别重算；预览不替代完整成片。

## 审查期间修正与最终限制

审查协作发现并由作者修正了：不可靠包误作可靠 replay 前驱；全局取消导致跨端知情；业务/依赖混接收端；非法业务参数；网络与 CPU 优先级混同；取消在可靠应用交付前生效；部分播放/网络静止缺少独立完成状态。独立检查器最初的截图边界使用 c2s，作者明确截图版本只在客户端评估后已改为 s2c；一次运行中作者继续编辑造成 SHA 首尾不一致也明确记录为待重跑，最终固定版本运行通过。没有为绕过失败而放宽数学期望。

该结论只认可声明模型的守恒、因果与业务政策。ACK/共享信用是 payload 逻辑单元教学合同，可靠接收暂存消耗到容量未受限的重组存储；不是实际 QUIC MAX_DATA、byte-cwnd、PTO、一般恢复或 CUBIC/BBR。25,000-byte 串行块不冒称符合路径 MTU 的 UDP 数据报。传输 ACK 不证明播放，取消不撤销已经发生的应用副作用，缺音不代表同质量加速。

六份规范的作用是限定语义，默认模型耗时/音频生成/截图夹具不由 RFC 证明。没有执行实际网络栈、编解码/模型、设备播放或 WAN 实验。图 12-4 的其他面板、固定拥塞/流控与原题同业务协议对照，及 C69 空口/多路径/费用能耗仍须独立完成；本研究候选通过不关闭 C68/C69。
