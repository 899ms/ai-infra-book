## 一、总体判断

建议把全书修改定义为一次**以读者理解过程为单位的图文修订**：一并调整概念引入、例题推导、图的分拆与补充、正文和图的先后关系，以及知识在不同章节的分工。

当前稿已经有很好的定量基础。第 4、6–12 章尤其已有贯穿算例、条件变化和章末设计题；第 12 章 Queqiao 案例还展示了观察、提出解释、校正基线、修正结论的过程。这些应当成为全书的骨架。需要改善的是读者从一个结论走到下一个结论时，能否看见对象、变化和推理中间步骤。

修改力度应有所区别：

| 章节 | 主要任务 | 建议力度 |
| --- | --- | --- |
| 1–3 | 建立对象和问题，控制概念进入速度，让模型结构逐步成为随时间变化的工作负载 | 重点调整局部结构，第二章尤其需要主线与资料表分层 |
| 4–5 | 建立硬件内部的物理图像，把执行顺序与资源取舍连起来 | 保留定量主线，补机制过程；5.2–5.3 作为已有样本 |
| 6–7 | 从分片和持有关系推导通信，再把通信映射到物理路径与事件 | 补齐逐轮状态，拆开逻辑与物理图，减少跨章重复推导 |
| 8–9 | 从请求、状态寿命和资源需求，走向配置与部署选择 | 保留综合设计，补共享、交接、路由和恢复的中间过程 |
| 10 | 从一次正确更新，走向训练步和长期可恢复进展；RL 再引入反馈 | 强化前后向与状态版本图，区分短时与长期时间尺度 |
| 11–12 | 从完整任务的完成条件出发，解释环境驻留、执行位置、交互与恢复 | 强化占用面积、状态机、分支和交互时钟，保留不同任务类型 |

“统一”应体现在读者每次都知道先看什么、怎样推导、怎样检验，以及同一种对象如何画。它不要求每节都有相同数量的图，也不要求把每章都组织成一个算子优化案例。

## 二、两本参考书分别借鉴什么

讲述方式以《计算机体系结构：量化研究方法》为参照，采用问题驱动、明确基线、性能模型、带解例题、敏感性分析、实际测量与设计取舍。目标是让读者能回答“改变条件后，还成立吗”，逐渐具备独立分析系统的能力。

本地未找到这本参考书原文，本方案借鉴其公认的定量分析与教材组织方法，不声称已经逐页研究其具体版本或照搬章法。用户之前所指的书名已明确为此书。

配图参照 Hands-On Large Language Models，主要借鉴三个特点：同一对象在连续图中保持可辨认；先呈现整体，再局部展开；每一步只突出当前需要理解的变化。例如 PDF 第 110 页／书内第 90 页的图 3-15、3-16，先画当前位置如何经过 attention，再在相同框架内展开评分与加权汇总，两图之间用正文建立联系。

此前已抽样查看跨多个章节的 12 个页面，本轮再次核看上述页面和第五章试改总览，并抽查当前第二、六、七、十、十一、十二章的代表图。参考证据与页码见[早期视觉研究](../figure-style-2026-09-10/README.md)。本轮完成的是全文阅读与代表图诊断，尚未对全部 201 幅做逐图出版验收。参考书的图片中有栅格文字，不能据其正文字体断言配图使用何种字体或精确字号。

## 三、建议确定的十条编辑原则

### 1. 用一个可回答的问题组织一个教学单元

每个单元先交代问题及已有条件，再解释机制，最后回答原问题。例如“扩大分块能否更快”“有缓存的实例是否值得等”“训练保存返回后，哪些进展已经可恢复”。

一个单元可以跨越数段正文、几幅图和一个例题。修改前先写清它的输入知识、读完应获得的判断能力，再决定原图保留、重排、拆分或补充。避免先把全章图片画完，再寻找位置插回正文。

### 2. 先建立具体对象，再引入符号和一般公式

先让读者看见一个输出、一份分片、一个请求、一块 KV、一份快照，再增加维度和规模。公式里的每一项应能指回图中或文字中已经认识的对象。

第五章的顺序可以推广：一个输出如何计算 → 相邻输出复用什么 → 输入块和累加器各保存什么 → 容量公式 → 访问量 → 并行度代价。其他章节分别换成“局部贡献如何求和”“前向值为何留给反向”“已交付输出如何恢复”，无需硬套矩阵图。

### 3. 名词在使用处可理解，必要时就地重述

首次使用说明“是什么、起什么作用、与相邻概念有什么区别”。只给英文全称、只放脚注或术语表都不够。图、图注、表头、实现名称和指标同样适用。

跨章、跨较长小节或改变语境时，再给一句简短定义。例如：“这里的后端是同一注意力 API 实际调用的实现；数学后端依次执行矩阵乘和 Softmax，Flash 后端采用分块与在线汇总，避免保存完整中间矩阵。”第十一章的“服务后端”指处理模型请求的服务，又需按该处语境定义。

重复定义是为了降低翻找成本；重复完整推导则要看本章是否增加新条件。既有要求见[全书编辑笔记](../../outlines/editorial-notes.md)。后续建立编辑用术语表，记录首定义、需重述的位置和允许的简写，读者不必依赖术语表才能继续阅读。

### 4. 先看机制，再量化收益，随后改变一个条件

建议的基本顺序是：问题和基线 → 对象与机制图 → 小例子 → 一般关系 → 条件变化 → 适用边界。实际测量放在读者已有预测之后，用于检验或修正预测。

第五章双缓冲先解释槽 A/B 的读写与复用，之后才算 20 μs 与 14 μs；FlashAttention 先看留下什么状态，再用两块数字解释重缩放，最后写一般递推式。这种顺序比先给结论曲线更容易形成直观理解。

不是每个短小节都必须包含全部步骤。一个完整单元应有完整推理，避免为了格式重复题设和结论。

### 5. 用连续图展示变化，复杂图按推理步骤分拆

同一对象尽量保持编号、位置、形状和颜色。先保留完整轮廓，再展开局部；对比图只突出发生变化的部分。

拆图的判断依据是：是否同时回答多个问题、是否跨越不同时间或空间尺度、是否必须缩小字号才能装下。例如第二章当前图 2-15 同时承担调用链、四模型计算量、同文本任务比较，应分开进入相应论述；第十章图 10-7 的调度过程、2 ms 等待来源和容量结果，应连续展开。

新增图用于补缺失的推理。没有独立解释任务的装饰图不增加；已经能清晰说明结论的数据图保留为数据图。数量由故事板确定，不把第五章 7→13 的比例外推到全书。

### 6. 分清容量、流量、时间和进展，分别给出计量边界

一份数据存多大、读取多少次、保存多久、传完何时能用，是不同问题。图上不得用相同的无标签长条混指这些量。

时间线尤其区分：任务提交、数据可用、消费者用完、资源释放、状态持久化。第七章目的缓冲不能在发送完成时覆盖，第十章异步保存返回不等于检查点提交，第十一章超时返回不等于工具停止，都应通过事件和状态变化讲清。

性能公式中的加法、最大值与最小值必须由执行关系推导：串行阶段相加，独立并发分支看最晚完成，共享资源先累计需求。不能把一个粗略 max 模型写成所有真实执行的等式。

### 7. 定量分析既给结果，也说明结果为何变化

每个核心例题至少形成“题设—推导—结果解释—改变条件”的闭环。保留单位、分母、整数取整和可行性条件。重点标出方案发生变化的位置，并解释是哪一项造成变化。

例如第九章的 CPU 读取／计算交点为 10 行，而 CPU 与 GPU 完整路径的选择交点在 78／79 行，两者回答不同问题；不能只留下“交点”这个笼统名词。平均需求满足容量之后，还需检查实际调度、波动和期限，不能从均值直接推出 p99。

### 8. 教学假设、推导结果和实测观察清楚区分

教学图可以缩小设备数、用整齐的数字，但必须说明省略关系；真实数据图保留样本、单位、计时范围与可解释的不确定性。图中直接写必要条件，其余完整环境和来源放图注及配套材料。

第五章约 2.6 ms 与 80 μs 是特定硬件、输入、精度、掩码及计时方式下的实现比较，不能把整个差值都归因于一个单独机制。第十二章 Queqiao 的基线修正应作为全书测量方法的代表。来源与限制随内容移动，不能在正文简化时丢失。

### 9. 核心推理与查阅资料分层，保持技术深度

主线保留决定机制和选择所必需的内容；完整模型矩阵表、厂商代际规格、版本核对和全部原始轨迹放入紧邻的扩展阅读或配套资料，并提供精确入口。先让读者理解一个代表路径，再比较其余变体。

第二章多模型逐矩阵表最需要这样处理。第四、六、七章的具体系统应解释某项结构选择，不宜让系统名称接连打断推导。重要反例、正确性约束、公式条件不因“简洁”而移走。

### 10. 每章形成能力增量，章末要求迁移方法

章首指出本章增加哪个问题，结尾交付可用于下一章的模型或判断。练习从复算到改条件再到设计；至少有代表性的解题过程，读者能学会如何组织分析。

全书主线可表述为：**任务产生计算与状态；执行位置和依赖决定搬移与等待；资源约束和完成目标决定设计选择。** 数据搬移是重要线索，计算、数值正确性、质量、故障和费用也各有独立约束。

## 四、配图和图文排版规范草案

### 最终显示尺寸优先

以第五章试改的 420 pt（约 148 mm）为当前全宽工作基准。正式开本确定后按真实版心重新设计；不通过整体缩小大画布塞入页面。半宽图另做布局，不能把全宽图直接缩半。

| 项目 | 建议定稿方向 |
| --- | --- |
| 图内主体文字 | 最终成书尺寸 12 pt 左右；必要辅助标签与刻度目标 11 pt，沿用试改的可读性底线 |
| 子图标题 | 约 14 pt；图号、正式标题和长说明置于图外 |
| 超出容量时 | 先缩短标签、移出解释、纵向分面或拆图；不以缩字号解决 |
| 中文字体 | 优先锁定思源黑体／Noto Sans CJK SC 的字体文件与版本；正文、公式、代码字体分别匹配 |
| 当前试改字体 | Arial Unicode MS 是样本的可复现选择，不直接认定为全书出版字体 |
| 底色与轮廓 | 白底，浅蓝／浅绿／浅橙／浅紫实体，深灰文字与细轮廓；不用阴影和装饰渐变 |
| 颜色语义 | 同一教学系列和同类对象保持一致；数据曲线允许按系列分色，配明确图例 |
| 箭头 | 表达数据、控制、依赖或引用时有明确区分；在需要时给局部图例，不让一个无说明箭头同时承担多个含义 |
| 线宽与强调 | 普通轮廓约 0.8–1 pt，主路径约 1–1.2 pt；强调当前变化，灰度仍能辨认 |
| 数据图 | 同条件对比用相同尺度；保留单位、实际零点／截断说明、对数标识、样本散点和必要误差 |
| 时间／面积图 | 标明按实际比例或按步骤示意；不可用等宽阶段暗示等长耗时 |
| 电子阅读 | 桌面按正文实际嵌入宽度验收；移动端优先纵向分面，必要时允许单图展开／横向查看 |
| 输出 | 可编辑绘图源、SVG、嵌字 PDF、PNG；阅读 HTML 与出版图稿同步更新 |

数学上下标允许正常缩小，但必须检查辨认度。第五章移动端保持 560 px 图宽并在图内横滑，是试读策略；全书不直接机械套用，应优先让较简单的图在窄屏自然阅读。

共享组件应覆盖七类表达：token／矩阵／张量；页与缓冲槽；设备与物理边界；队列与消息；资源时间线与占用区间；引用／版本／提交状态；定量曲线与决策区域。共享的是基本画法，具体图仍按机制编排。

图文的推荐交替顺序为：提出问题并定义对象 → 图展示发生的变化 → 正文引导读者沿具体箭头或色块阅读 → 公式和小算例 → 图显示量化结果 → 解释改变条件后的选择。图注应能帮助单独翻阅，正文则负责推进推理，两者不整段重复。

| 概念 | 建立完整理解的位置 | 后续章节新增的问题 |

## 六、实施顺序与交付

**当前评阅点。** 作者先 review 本方案的教学原则、逐章调整范围和样式方向。全书修改在此后开始。这一暂停来自本次任务明确要求的“先 review，再完整修改”。

**阶段 0：把规范变成可执行样张。** 以 5.2–5.3 为基准，补充四种有代表性的图文样张：第 2 章共享关系、第 7 章远程交接、第 10 章训练状态与调度、第 11 章恢复分支。分别覆盖对象图、拓扑／控制图、复杂时间线和概率树，放进真实书页验证。建立共享绘图层与字体配置；形成术语表、跨章对象约定和逐图故事板字段。这个阶段是已批准全书工作的首批交付，不额外要求作者为常规实现逐项批准。

**阶段 1：第 1–3 章。** 先完成入门概念和阅读顺序，确定后面可依赖的符号、生成计数和状态术语。第二章的大表分层是此阶段的主要结构工作。

**阶段 2：第 4–5 章。** 对齐硬件资源和程序执行的分工。保留 5.2–5.3 的成功讲法，将第五章其他部分纳入同样规范；重新检查整章过渡，防止试改段落与其余部分脱节。

**阶段 3：第 6–7 章。** 固定设备、分片、归约和物理边界画法；完成逻辑数据分布 → 通信轮次 → 物理路径 → 完成事件的连续讲述。

**阶段 4：第 8–9 章。** 用相同请求与 KV 对象连接实例调度和分布式部署，强化本地复用与跨位置交接的区别，核对容量、服务率与期限的综合设计。

**阶段 5：第 10 章。** 完成前后向、状态分片、检查点及 RL 的独立图形系列，接好第三章的负载概念和第六、七章的通信基础。

**阶段 6：第 11–12 章。** 将前面的方法用于完整任务、环境与交互，控制框架和协议名称的密度，保留 Queqiao 的归因修正作为综合实证案例。

## 七、验收标准

**教学验收：** 随机选一个核心单元，读者应能指出对象、解释箭头、把公式每项对应到机制、独立复算一个小例子，并在改变条件后解释选择为何变化。逐章具体问题见[逐章修改方向](chapter-directions.md)。

**术语验收：** 核心名词首次出现处有用途定义；长距离再次出现时有简短提醒。特别检查 backend、worker、rank、state、吞吐、利用率、窗口、提交、恢复、有效样本等多语境词。

**视觉验收：** 在真实书页宽度、桌面和窄屏查看；检查字是否足够大，颜色失去后是否仍可辨识，数值图是否采用合理尺度，箭头与布局是否误导。文字边界自动检查通过后仍须人工查看，不能把“没有越界”当成“读者看得懂”。

**技术验收：** 执行各章现有相关构建与验证，核对单位、数值、引用、图号和导出一致性。结构调整不应无意改变计算结果与来源；必要纠错单独记录理由和证据。教学假设不升级为实测，方法比较不升级为单因素因果结论。

**全书验收：** 核对章节之间的定义和新增知识，完整审阅习题所需前置知识；检验正文图文顺序、分页、交叉引用及资料入口。目标是读者能沿全书逐渐构建系统认知，而非仅得到一套外观相似的图片。

本次最需要作者评阅的是：是否同意以教学单元为改动边界；是否同意第二章等密集材料分层；是否接受主体约 12 pt、辅助约 11 pt 的尺寸方向；以及逐章建议是否保留了希望强调的技术重点。正式开本和字体尚可在首批样张中细化。
