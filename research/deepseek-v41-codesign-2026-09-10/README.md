# DeepSeek V4 / V4.1 Flash：基础设施驱动模型设计的证据与修订建议

调研日期：2026-09-10。此次只保存调研、来源核对和复算结果，不修改正文、大纲、图和计算实现。

## 判断

这是全书“模型与基础设施双向协同”主线的强案例。V4.1 的官方标题就是 **Pushing the Limits of KV Cache Compression**，报告开篇直接从长轨迹 Agent 的 Prefill、HBM、SSD／host memory 和缓存迁移带宽出发，推导架构、数值格式、状态管理的联合改动。比“看到一种结构有效率收益，再推测其动机”的证据强得多。

但不宜写成“为了 Infra 速度，V4.1 比 V4 牺牲了更多模型表达能力”。更准确的是：**模型限制了部分远程信息表示、逐层选择与精确状态恢复的自由度，并在训练中适应这些限制，同时在其他维度增加容量或保留灵活性，以改善系统预算下的能力与成本。** 自由度受到约束、单项近似引入误差、最终任务能力下降，是三个需要分别论证的命题。

## 2. 哪些限制确实存在，哪些结论不能推断

| 机制 | 系统收益 | 限制的自由度／潜在误差 | 保留或补偿 |
| --- | --- | --- | --- |
| V4 的 CSA／HCA | 缩短全局历史表示，降低容量与注意力工作量 | 多个历史位置被合并；CSA 只读取选中条目，原始位置不能全部逐一直接访问 | 学习压缩内容和权重，每层保留局部 SWA |
| V4.1 CED | 大部分输入仅执行编码器，解码器全局 KV 由编码器末层产生 | 解码器全局 KV 不再来自各层自身隐状态 | 投影可按层设计；局部 SWA 仍保持逐层计算深度 |
| CSA2 跨层 KV 共享 | 少量拥有者保存全局 KV，避免逐层重复保存 | 复用层不独立生成自己的全局 K/V | 各层仍保留独立 Q 与局部 SWA；共享 K/V 不等于共享注意力输出 |
| Top-K Reuse | 跳过部分索引计算 | 复用层不能独立选择历史位置 | Reindex 层重新选择 Top-K，Full／Reindex／Reuse 分工 |
| 层级索引 | 后续解码索引器只处理最多 16,384 候选 | 早期筛掉的位置不能在本次查询的后续 Reindex 中重新进入全局候选 | 初始 Full 索引仍扫描全局；各 Reindex 可在候选内分别选 512；局部路径继续存在 |
| FP4 主 KV | 更少存储与传输字节 | 缓存数值精度降低 | 后训练引入 QAT；敏感的局部 SWA 保留 FP8 |
| SWA Bounded Replay | 不必长期持久化局部 KV；只重放 128 token | 是近似恢复，不保证与完整精确重放逐位或语义等价 | 短期 host DRAM 缓存照常存在；报告称测评退化很小，仍承认未测边界风险 |

“强迫模型学会稀疏注意力”可以理解为训练时就让模型在受约束的信息通路中学习。报告明确说从头以 64K 序列进行稀疏训练，没有 dense warmup；层级候选限制在后训练阶段加入，训练／推理使用相同候选域；FP4 主 KV 也在后训练中进行 QAT。但不能由此声称训练恢复了所有被舍弃的信息。

尤其要避免说 V4.1 “沿序列压缩得更狠”。V4 Flash 主干是 43 层：2 个纯 SWA、21 个 4:1 CSA、20 个 128:1 HCA。V4.1 是 40 层：前 2 个纯 SWA，其余为 CSA2；编码器全局压缩比 2:1，解码器全局压缩比 1:1，取消 HCA。其更小缓存主要依赖**跨层共享与降低精度**。从某些维度限制自由度的同时，它反而保留了更细的历史位置粒度。

### 论文对于“能力损失”的证据强度

报告第 1 节把 FP4 的影响描述为 marginal performance degradation，把有界重放描述为 negligible performance degradation。第 2.4.4 节说明：

- 索引采用硬件兼容性更好的 OCP MXFP4，虽然实验中有其他格式精度更高。这是非常直接的硬件约束进入模型／数值设计的证据。
- 主 KV 在注意力前反量化，主要目标是减少存储，而非直接把矩阵乘法变成 FP4；不应据“4-bit cache”声称注意力计算快四倍。
- RoPE 前量化精度略好，但增加 decode 开销，因此采用 RoPE 后量化。
- 保留 SWA FP8，因为该部分对量化敏感。
- “去掉第二级全局 scale 未测出精度下降”只针对去掉该 scale，不能扩张为所有 FP4 KV 均无误差。

第 6 节明确承认 CSA2 选择错误与 SWA 近似恢复可能在未覆盖的边界条件中造成能力退化，同时报告其已测场景未见系统性退化。

**未找到足以量化每一项自由度约束损失的完整、等规模等数据架构消融表。** 发布模型间的能力表不能代替该消融。V4.1 主干由 284B 增至约 552B，又加入约 196B 的 Engram、训练数据和后训练发生变化，成为多模态模型。整体评价更好与单项结构近似可能有损完全可以同时成立；也不能把所有新增训练和 Engram 都断言为专门弥补 KV 压缩的损失。

## 3. 与仓库计算交叉核对

复用已有 `kv_comparison.py` 与 `v41_flash.py`，未修改实现。对应 11 项单元检查通过：[日志](calculation-tests.log)。结果另存为 [缓存比较](cache-comparison.json)和 [8K 配置／权重／专家矩阵审计](v41-8k-audit.json)。没有运行模型质量或 GPU 吞吐实测。

### 3.1 全局缓存的 890 B/token 可以从布局推出来

V4 生产布局主 KV 每条 584 B，CSA 索引每条 68 B：

`21 × (584 + 68) / 4 + 20 × 584 / 128 = 3514.25 B/token`。

V4.1 主 KV 是 `512/2 + 512/16 = 288 B`，索引是 `128/2 + 128/32 = 68 B`。四个全局 KV 拥有层（0 起始编号为 2、8、14、20）分别保存三个半速历史和一个全速历史：

`(3/2 + 1) × (288 + 68) = 890 B/token`。

全局长期增长斜率之比为 **3.9486**。这是“全局主 KV + 索引”，不含局部窗口、权重、压缩器缓冲、候选／Top-K 元数据、分配器、并行副本或工作区。奇数位置还需按每层压缩完成边界取整。

### 3.2 同一长度下，容量与读取不是同一个数

下表 B=1，K=1024，单位 MiB；采用各自已公开生产布局。驻留量只合计全局历史与有效 SWA。decode 读为逐层所需主历史与索引的逻辑操作数载荷，不是实测 HBM 流量；查询为该可见长度的末位置。

| 可见历史 | 模型 | 全局历史 | 加上局部窗口 | decode 主历史读 | decode 索引读 |
| --- | --- | ---: | ---: | ---: | ---: |
| 8K | V4 Flash | 27.455 | 30.521 | 9.767 | 2.789 |
| 8K | V4.1 Flash | 6.953 | 9.531 | 7.922 | 3.453 |
| 128K | V4 Flash | 439.281 | 442.347 | 20.460 | 44.625 |
| 128K | V4.1 Flash | 111.250 | 113.828 | 7.922 | 25.500 |
| 200K | V4 Flash | 686.377 | 689.442 | 26.876 | 69.727 |
| 200K | V4.1 Flash | 173.828 | 176.406 | 7.922 | 37.453 |
| 1M | V4 Flash | 3514.250 | 3517.315 | 100.304 | 357.000 |
| 1M | V4.1 Flash | 890.000 | 892.578 | 7.922 | 174.250 |

8K 时总逻辑历史读取只改善约 **1.10 倍**；1M 时约 **2.51 倍**，都不是四倍实测加速。V4.1 的主注意力所读条目有界，但早期索引仍需随长度扫描；深层索引有界不意味着整模型所有工作严格 O(1)。跨层共享会减少唯一驻留数据，但多个层仍访问它；L2 命中、融合、并行与布局将决定实际 HBM 字节。

### 3.3 持久化缓存的八倍来自另一套账

报告第 3.2.1 节给出的约 1/8，是在相同工作负载下：V4 原部署持久化缓存约一半为多轮位置保存的 SWA，V4.1 不再长期持久化这些 SWA，再将全局部分缩为约 1/4。因此近似为 `1/2 × 1/4`。它不是模型配置无条件保证的每 token 比例。

V4.1 仍将短期 SWA 放在分布式 host DRAM 池中，TTL 为分钟级；全局缓存保留更长时间。SWA miss 才进行近似重放。不能写成“完全不存 SWA”或“所有 SSD 数据都缩小八倍”。

### 3.4 不能直接将新数字塞进原表

当前第二章 8K／200K 图使用 BF16 逻辑状态和未按精度加权的矩阵 FLOPs。V4 的对应状态为 74,203,136 B 和 1,426,866,176 B，与上述生产布局不在同一精度口径。应保留原表计算基线，另设实际缓存布局比较，明确主要 KV、索引、SWA 和元数据边界。

V4.1 报告 Figure 2 对 BF16／FP8／FP4 FLOPs 分别乘 1／0.5／0.25，而原书给出数学运算数。不能直接在同一条曲线上加点。

已有 V4.1 适配器声明 `complete_forward=False`。它核算的是缓存、checkpoint 和专家矩阵子项：8K 输入下，CED 有界重放的专家矩阵约 82.443 TFLOPs，V4 约 124.107 TFLOPs；V4.1 单步 decode 专家矩阵约 19.818 GFLOPs，V4 约 15.150 GFLOPs。这里只说明更大模型可以输入阶段少做、输出阶段多做，不是完整 Prefill 或 Decode 的速度结论。

公开参考 `Transformer.forward` 仍逐层前向；参考索引实现先对完整索引矩阵打分，再应用候选限制。不能把参考代码路径的实测等同于论文 CED 部署与选择性索引读取。完整 forward 接入原书比较前须补齐 attention、索引、mHC、Engram、视觉及草稿范围，并分别保留参考与生产调度。

仓库现有 Qwen3-8B／V4 Flash 配对检索只是在约 0.5K／2K 输入的八道短语题同为 8/8，不能支持百万上下文、V4.1 或结构消融的质量判断。

## 5. 最有价值的思想实验与后续验证

1. **HBM 容量／带宽近乎免费。** 第一轮保留 V4.1，独立提高容量和带宽，索引算力、Prefill、SSD 迁移与工具等待仍在。第二轮再考虑增加 KV 拥有层、提高精度或扩大 Top-K。带宽便宜不代表 dense attention 的计算便宜，不能预言一定恢复全注意力。
2. **候选池漏掉真正相关的块。** 让答案依赖一个先前 Full 层低分块，而后层语义处理才显出其重要性；比较不同候选池大小、干扰块数量、多跳检索与引用完整性。它能测试不可重新进入候选的风险，但不能预先断言一定失败，因为其他通路可传递相关信息。
3. **相同权重、相同提示，命中与恢复两条路径。** 比较保留精确 SWA、完整精确重放、有界 128-token 重放。测 logits／输出差异、任务成功率、时延和传输，不要求近似恢复逐位相同。尤其覆盖摘要缺失、跨窗口依赖、多轮恢复边界。
4. **同预算而非只同模型。** 固定质量门槛与设备／能耗／费用后，比较压缩是否允许更长上下文、更高并发、更大主干或更多有效训练。额外推理并非必然提高质量，必须再测。

若要下“结构导致多少质量损失”的因果结论，需同规模、同数据、同训练预算的重训练／消融；直接把一个已训练稀疏模型的 Top-K 改成 dense，或开启更大的候选池，并不能自动成为公平的稠密基线。现阶段可以引用论文明确的动机和所报告的退化范围，并把未测边界作为思想实验，不应写出不存在的消融结果。

## 可采用的核心表述

> DeepSeek V4.1 Flash 将 KV 的存储、传输和恢复代价前移到模型设计中：部分层共享全局表示，部分层复用检索位置，主 KV 在低精度条件下参与训练，局部状态允许按有限窗口近似恢复。它减少了某些信息通路的自由度，却同时保留独立查询与局部计算，并采用更细的历史粒度和更大的模型容量。这说明，基础设施约束能够塑造模型怎样保存和使用信息；设计目标是在任务质量条件下重新分配有限资源。报告中的整体能力提升，不能单独证明各项近似没有损失；其承认的选择错误和恢复边界，也不能被扩大为整体能力必然下降。
