# 全书配图体例改造建议

日期：2026-09-10。范围：参考书抽样视觉分析、十二章正文图片引用盘点、规范草案、两幅独立样图。此轮没有替换正文插图，也没有重建各章 HTML。

## 判断

建议全书采用接近《Hands-On Large Language Models》的教学插图体例：白底、浅色实体、深色细轮廓、大标签、紧邻对象的短注释，以及连续推进的机制讲解。真正需要统一的是图形语言和最终版面上的可读性。为此要调整信息组织、绘图组件和输出排版，不能只换调色板或批量修改 fontsize。

本书现有图已经有蓝、绿、橙的共同基础，许多新图也已改成机制图。主要问题在于画布和字号比例、过长标签、跨章组件差异，以及同一图承载过多层次。可复算数据、已有来源锁、外置图号和图注应继续保留。

以拟定最终宽度 **420 pt ≈ 148 mm** 做初筛：193 幅 SVG 均解析到字号；191 幅至少有一处小于 8 pt。每幅图最小字号的中位数约 5.48 pt，最小约 2.92 pt。算法是 `SVG 字号 × 420 / SVG 原始宽度`，包含刻度、图例、公式小字，不等于每幅图的主体标签都只有这么大。这个数值是候选版心下的估算，不是已印刷成书的测量；正式验收应区分主要标签、辅助标注和数学上下标。

例如 14 英寸画布上的 12 pt 字，缩到 420 pt 宽时约为 5 pt。提高 PNG 的 dpi 只增加清晰度，不增加字的相对大小。

代码层面：各章 `build.py` 常分别定义配色、字体、`canvas/box/arrow/save`；此外有 `teaching_figures.py`、各章 `illustrations.py`、`extra_figures.py` 等补充入口。部分章节 HTML 将 PNG 内嵌；所以只修改 SVG 或通用 rcParams 并不会自动改变全部阅读版。

## 建议采用的统一规范 v0.1

以下为初稿，420 pt 是样图基准。实际开本确定后应按版心重新验证，不能靠整体缩图适配。

| 项目 | 建议 |
| --- | --- |
| 成书图宽 | 全宽以 148 mm 为工作基准；小图可为 72 mm，但须单独设计字号和布局 |
| 主体标签 | 最终成书 11–12 pt；子图标题 13–14 pt；数值与坐标轴通常 10–11 pt |
| 辅助字 | 原则上不低于 9 pt；数学上下标允许例外；不能把必要解释降成小字 |
| 网页阅读 | 桌面主体标签目标不小于 16 CSS px；固定缩小到手机不能保证可读，密集图提供分面或原尺寸展开 |
| 字体 | 正式版优先锁定思源黑体 / Noto Sans CJK SC 的具体字体文件，Regular + Medium；代码另用等宽字体，变量保持数学排版 |
| 样图字体 | 本机 Arial Unicode MS，用于验证尺寸和结构；不是正式字体定稿 |
| 线条 | 深灰轮廓约 0.8–1 pt；主流程约 1–1.2 pt；辅助边界约 0.5–0.7 pt |
| 底色 | 白底，无阴影或渐变；分组先用留白，必要时用淡灰边界 |
| 填充 | 浅蓝 `#CBE3F3`、浅绿 `#CFE8DB`、浅橙 `#F9DEC0`、浅紫 `#DDCDE8`；文字 `#252525`，轮廓 `#414141` |
| 强调 | 一幅图优先一个强调对象；颜色必须同时配标签、线型或位置，灰度也可识别 |
| 标签 | 框内一般 1–2 行短语；长假设、来源、推导移入图注或正文 |
| 图注 | 图号和完整标题放图外；先说图解释的结论，再说明阅读方法与条件；图内保留必要子图标题 |
| 数据图 | 保留真实坐标、单位、对数尺度、误差和假设；细网格、少刻度、直接标关键值；无装饰性 3D |
| 输出 | 源代码与数据为编辑源；交付 SVG、嵌入字体的 PDF、高清 PNG；网页与印刷取对应格式 |

颜色应在相同概念反复出现时保持一致，但不要强制全书每种颜色只表示一个技术名词。建议机制图中浅蓝表示数据或状态、浅绿表示处理、浅橙表示本步输入或关注对象；数据图可按比较系列分色，并明确图例。例如样图的橙、紫分别表示中间 T、Z，并非强行把它们解释成“计算”和“通信”。红色留给错误或失败，避免同时用于普通组件。

## 图形语言：统一基础，保留图型差异

1. **机制流程图**：每图回答一个问题，主要链路优先 3–5 步；用对象变化解释计算，不能只是把正文装进方框。整体图与局部图复用位置和形状。
2. **布局与拓扑图**：固定设备边界、张量分片、小页块和队列组件；边标明方向和传输对象。卡数太多时画代表性部分，并写明省略含义。
3. **时间线**：统一时间从左到右，资源按行排列；对比方案共用时间尺度；画出等待、重叠和缓冲占用，不以缩短长条伪造收益。
4. **定量图**：只保留验证结论所需的曲线与标注，比较条件一致；机制说明单列小图，不能挤进同一个坐标系。
5. **具体对象示意**：token 格、矩阵格、包、页、分片保持可识别形状。小图标只在确实帮助辨识对象时使用；大规模重复可省略，不压缩到看不见。

最需要借鉴参考书的是连续叙事：例如先说明单块计算，再显示重复读取，再引出双缓冲。读者应看到相同对象怎样变化，而不是每幅图重新学习一套颜色和结构。

## 实施顺序与验收

**第一步：确定版心与图形规范。** 以上述尺寸制作一组包含六类复杂度的样图，在书页中查看，而不是只放大单张 PNG。同步确定中文字体文件、图注样式和移动端策略。

**第二步：建立共享绘图层。** 建议放在 `manuscripts/figure_style/`，提供主题、实际宽度、字体层级、组件、导出和检查。机制图保持可控的矢量绘制；数据图继续用 Matplotlib 并读取现有结果文件。为硬编码 fontsize 和独立补图入口逐一接入共享层，避免只改默认值。将 data、drawing、HTML embedding 分成清楚的步骤，但无需为了样式迁移重写计算项目。

**第三步：逐图分类迁移。** 在清单增加“图要回答的问题、保留元素、移入图注的内容、是否拆图、图型、生成入口、状态”。简单数据图可先批量应用主题后人工复查；高密度机制图逐图重新排版；同一技术对象跨章出现时集中统一。建议先用第 2、5 章建立机制图与时间线模板，再处理第 6、7、9 章的拓扑，最后覆盖其余章。所有 193 个当前引用都必须有迁移结论。

**第四步：整章阅读验收。** 重新导出图片、图数据索引、manifest 和内嵌 HTML，核对文件引用和图注编号。拆图时更新正文引导句和指代，不把新图机械堆在原位置。目录中的历史图不纳入发布集合，但本轮无需删除。

验收包含两层：

- 自动检查：字体来源、最终尺寸与字号层级、文字出界、缺字、引用失效、导出格式一致、数据与来源锁是否保持；字号检查应读取 SVG/CSS/transform 的实际效果，不能把本轮简单正则当成最终排版校验器。
- 人工检查：PDF 实际尺寸、桌面正文嵌图、移动端展开、灰度辨识，以及箭头是否误导、标签是否遮挡、比较尺度是否一致。自动边界检查不能证明没有所有遮挡，也不能证明教学讲解清楚。
