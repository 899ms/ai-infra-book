# ASR receive configuration

Use the exact actual WAV/Whisper transcript pair and0.622926892s measured GPU service replay from ../speech-records. No new model inference occurs. Fixed Docker network-none netem80ms RTT,20Mbit/s,0.1% loss,2CPU/2GiB. Compare defaults,64KiB,4MiB receive configurations using the same TCP SO_RCVBUF and QUIC initial connection/stream-credit intervention as ../window-sizing; keep send buffers/congestion algorithm unchanged. TCP readbacks and raw TCP_INFO plus QUIC parameters/MAX frames must verify the actual intervention.

Three outer trials use a predeclared position-balanced mode order: default/64k/4m;64k/4m/default;4m/default/64k. Each configuration occupies each position once, avoiding the coincidentally identical mode order in the earlier image run. This is not retroactive replacement of the image results. Protocol order uses the archived seeded shuffle, held constant across modes within each trial. Each subrun warms one request per protocol, then uses one fresh connection with two sequential formal requests for each protocol. Nine fresh containers ×6 exchanges=54 (36 formal18 warmups).

Every request uploads the full original WAV, waits the recorded model service, returns the original transcript and verifies exact UTF8 plus byte identity. This measures complete recognition-result delivery, not streaming ASR, acoustic correctness or per-protocol quality. Preserve all samples and failures. The small decoded text result and1.18MB upload can respond differently to receive tuning than the large RAW/JPEG workload; do not substitute image measurements. Common120s request deadline and20s handshake limit, actual connection identity/TLS/ALPN/qlogs, netem queues and container resources/cleanup are checked. Reuse-on pair medians mix the first fresh and second reused request.
