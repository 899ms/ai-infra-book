## 这本书要做什么

> 读完这本书，给你一组新的约束——新的制程、新的电价、新的模型形态、新的延迟要求——你应该能自己推导出该造什么。
>
> **知识会过时，推导程序不会。**

**主线**是一个可计算的代价分解：

```
每 token 的代价 = 计算 + 数据移动 + 同步等待
```

三项之间可以互相兑换，**其相对代价由硬件决定**——并且不只由硬件决定，也由电价、土地、电网接入与供应链决定。同一套代价模型，不同的要素价格，得到不同的最优解。

**方法**是 back-of-envelope 估算，承自 Jeff Dean 与 H&P《计算机体系结构：量化研究方法》。全书统一使用**五步推导**：写下需求 → 写下供给 → 相除找瓶颈 → 列出可兑换项 → 算出兑换后的新瓶颈。

## 定位

现有作品各自站在栈的某一层上：**How to Scale Your Model**（DeepMind）方法同构但把算子与集合通信当作外生量，且以 TPU 为主；**Ultra-Scale Playbook**（HuggingFace）只有训练、只有 GPU；**MLSysBook**（Harvard / MIT Press）广度极大但偏教育与边缘侧；**Efficient Processing of DNNs**（Sze / Emer）止于芯片层且成书于 LLM 之前。

本书写的是**相邻六层之间的传导**，从「制程与功耗作为输入约束」到「Agent 负载」，并用同一把尺子横向比较 GPU / 昇腾 / TPU 等多种架构——这是一个结构性位置：Google 不能写昇腾，NVIDIA 不能中立评价任何人，华为不能写 NVIDIA。

四条接缝（栈中泄漏最严重的四条边界）：

| 边界 | 它存在的证据 |
| --- | --- |
| 算子 ↔ 片上存储层次 | Flash Attention |
| 并行策略 ↔ 互联 | 「TP 不超过 8」这条经验法则 |
| 模型架构 ↔ 推理系统 | GQA / MLA / MTP |
| 超节点 ↔ 制程与功耗 | NVL72 的 72 |

## 写作原则

**最耐久的东西放在中心，最独特的东西当作证据。**

检验方法：三年后书里每一个具体数字都错了，它还教不教得会人东西？答案必须显然是「是」。推论：**中心不仅要耐久，还必须少**——若能点出三到五条 2040 年仍成立的东西，那就是内核，其余全是可修订内容。
