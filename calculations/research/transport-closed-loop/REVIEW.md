# 独立审查记录：限定范围 PASS

最终冻结版本实际通过 9 组独立检查：五个预先固定的物理时间小例、三个路由器容量/同刻边界，以及 20/100Mb/s、每方向传播 50ms、模型 0.3 秒的 30MB 上传/5MB 响应。`independent-check.json` 记录 calculate hash 3326f3265ecfb4f0ef96527591f96a143117fb5bd47f3e7ca8604bee7eb3d6c0 和 sender hash f81ca5ff2f7db8d1b3f4f53462a63f5c5a628ebe054661146ca5e0e26accf16a。结论只覆盖该版本和列明场景。

独立 checker 不调用 sender 的区间合并、窗口或计时 helper 生成期望；五个确定时刻取自实现前的 `root-oracles.json`。逐包另核序列化时长、同方向无重叠、28B 头账、PN 单调且不重复、ACK 所引用包真实到达、发送事件时间与线上开始相同、独立合并的接收区间和绝对 offset 消耗。丢包两例明确重发新 PN/旧区间及线上重复计费。根第三例保留 MAX 的独立 ACK 在上行额外占用 23/307 秒这一修正。

首轮大例是显式选择模型 1 秒的变体，并非原书 0.3 秒配置；该历史结果保存在 `independent-1s-variant.json`。原书 0.3 秒已通过实际输入重新运行，完整响应为 22442797/1562500 秒（14.36339008 秒），模型结束为 8322913/625000 秒。没有以机械减去 0.7 秒代替执行。此轮 `calculate.py` hash 为 8942c0887ca6e14f1b59ad720d17a907554652e2b80d3ec24fa6143bd36bc707，sender 为 f81ca5ff2f7db8d1b3f4f53462a63f5c5a628ebe054661146ca5e0e26accf16a；随后已在上述最终冻结版本重新执行并得到相同时刻。

首轮大例使用显式 `sender.numeric_quantum=1e-12`：59,932 次实际发送，35,000,000 有效字节，线上 39,554,832 字节；上行 31,934,952、下行 7,619,880。上传完整时刻 8135413/625000 秒，1 秒模型之后，完整响应为 23536547/1562500 秒。每方向 STREAM payload 精确覆盖一次，无丢失路径没有静默重发或重复贡献。

第一轮以默认 exact 模式运行大例实际遇到 Fraction 分母增长导致 Python 4300 位整数转字符串限制。没有关闭该限制来冒称成功。大例改用已声明量化模式，精确小例仍维持 Fraction；实际逐项核验了 59,800 条局部原值、舍入值与误差，满足 new−old=error 且绝对误差不超过 1e-12，局部误差不等于整个非线性轨迹的误差保证。默认精确模式的明确有限预算拒绝由作者补充。

本检查不能替代 sender 的原 14 trace 等价性检查，也没有独立证明全部 RTT/loss/NewReno 分支。除末段三小例之外的有限队列丢弃、接收内存、长时 ACK 丢失、persistent congestion、ACK 策略变化、多流、媒体/取消、CUBIC/BBR 适配仍须相应单独样例和审查。这里只报告完整 request 与其反馈的有限参考路径，不是生产 QUIC 或 C68 全部完成。

新增独立路由器小例使用 1 秒源串行、1 秒前向传播、2 秒路由器串行和 1 秒后续传播。三个包在 2/3/4 秒进入路由器。等待容量 0 或 1227B 在 3 秒丢第二个 1228B 线上包，4 秒服务结束优先于同刻第三包准入；容量恰为 1228B 则按 2/4/6 秒开始服务。截止 6 秒尚无 ACK 到发送方，flight 仍为 3600B、loss 为空，实际接收仅首个 1168B 区间。这里核实际源发送后的队列丢弃与完整包容量等号，未覆盖全部队列拓扑或长期恢复。
